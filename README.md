# Vibe App Laravel Starter

Vibe App is a clean Laravel 13 starter project for a future AI-powered business generator. It includes a homepage, a CSRF-protected form, basic server-side validation, and a placeholder generation response. The frontend requires no Node.js build step: Tailwind CSS is loaded from its browser CDN, while project CSS and JavaScript are served directly from `public/`.

## Requirements

- PHP 8.3 or newer
- Composer 2
- MySQL 8 or a compatible MariaDB release
- PHP extensions required by Laravel: Ctype, cURL, DOM, Fileinfo, Filter, Hash, Mbstring, OpenSSL, PCRE, PDO, Session, Tokenizer, and XML

## Install a new copy from scratch

Create a fresh Laravel project with the latest stable release:

```bash
composer create-project laravel/laravel vibe-app
cd vibe-app
```

This repository is already created and customized. To install its PHP dependencies after cloning or uploading it, run:

```bash
composer install
```

Create the local environment file on Windows PowerShell:

```powershell
Copy-Item .env.example .env
php artisan key:generate
```

On macOS or Linux:

```bash
cp .env.example .env
php artisan key:generate
```

Update the MySQL placeholders in `.env` before using database-backed features:

```dotenv
APP_NAME="Vibe App"
APP_ENV=local
APP_DEBUG=true
APP_URL=http://localhost

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=your_database_name
DB_USERNAME=your_database_user
DB_PASSWORD=your_database_password
```

Start the local development server:

```bash
php artisan serve
```

Open `http://localhost:8000` in a browser. No `npm install`, `npm run dev`, or Vite build is required.

## Transactional order emails with Resend

The booking flow sends an order confirmation to the customer and a separate new-booking notification to the owner after a customer places a request. The admin dashboard also emails the customer whenever the order status changes. Customer messages use published Resend templates. The owner notification is generated by the app and includes the full order summary plus a link to the admin dashboard. All messages use stable idempotency keys and a job that supports retry backoff when a queue worker is configured. The default `QUEUE_CONNECTION=sync` sends after the HTTP response without requiring a separate queue worker.

Set these values in the private `.env` file:

```dotenv
MAIL_MAILER=resend
MAIL_FROM_ADDRESS="orders@mail.tonosbellyssimo.online"
MAIL_FROM_NAME="Toño's Bellyssimo"
RESEND_API_KEY=re_your_sending_only_key
RESEND_ORDER_CONFIRMATION_TEMPLATE=bellyssimo-order-confirmation
RESEND_ORDER_CONFIRMED_TEMPLATE=bellyssimo-order-confirmed
RESEND_ORDER_DECLINED_TEMPLATE=bellyssimo-order-declined
RESEND_GCASH_PAYMENT_TEMPLATE=bellyssimo-gcash-payment
GCASH_QR_URL=https://tonosbellyssimo.online/images/gcash-payment-qr.jpeg
ORDER_NOTIFICATION_EMAILS=you@example.com,backup@example.com
```

The comma-separated environment value supplies the initial recipient list when the notification settings table is first created. After deployment, an authenticated administrator can add or remove recipients from **Email alerts** in the admin dashboard without editing `.env`.

The production sender is `orders@mail.tonosbellyssimo.online`, using the verified Resend subdomain. Keep the API key out of source control, then run `php artisan config:clear` after updating `.env`.

## Application routes

| Method | URI | Controller method | Result |
| --- | --- | --- | --- |
| GET | `/` | `HomeController@index` | Renders `resources/views/home.blade.php` |
| POST | `/generate` | `HomeController@generate` | Validates `business_type` and returns `Generated successfully` |

The form includes Blade's `@csrf` directive. The `business_type` field is required, must be text, and may contain at most 100 characters.

## Shared hosting deployment

1. Select PHP 8.3 or newer and enable Laravel's required PHP extensions in the hosting panel.
2. Upload the complete project outside the public web root when possible.
3. Set the domain's document root or web directory to the project's `public/` directory. For example, if the project is `/home/username/vibe-app`, the full document root is `/home/username/vibe-app/public`. In DreamHost's Web directory field, this is typically entered as `vibe-app/public`. Never point the domain at the Laravel project root because `.env` and other private files would become exposed.
4. Create a production `.env` from `.env.example`. Set `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL=https://your-domain.example`, a fresh `APP_KEY`, and the real MySQL credentials.
5. Run the following commands from the project root over SSH:

```bash
composer install --no-dev --optimize-autoloader
php artisan key:generate --force
php artisan migrate --force
php artisan optimize
chmod -R ug+rw storage bootstrap/cache
```

Generate the application key only during the first deployment. Replacing the key later invalidates encrypted cookies and any data encrypted with the previous key.

The included `public/.htaccess` routes Apache requests through Laravel's `public/index.php`. On DreamHost, the domain web directory can be changed from the website settings panel; set it to the project's `public` folder.

If Composer is unavailable on the host, run the production Composer install locally with a compatible PHP version and upload the resulting `vendor/` directory with the rest of the application.

## Production reliability on Hostinger

The application includes a public `GET /health` endpoint for uptime monitoring. It returns HTTP 200 only when Laravel and the configured database are reachable, and HTTP 503 otherwise. The response deliberately excludes exception messages and credentials. Point an external uptime monitor at `https://your-domain.example/health`; keep Laravel's lightweight `/up` route as a secondary boot check.

Use these production settings in the private `.env` file:

```dotenv
APP_ENV=production
APP_DEBUG=false
LOG_CHANNEL=stack
LOG_STACK=daily
LOG_LEVEL=warning
LOG_DAILY_DAYS=30

QUEUE_CONNECTION=database
QUEUE_FAILED_DRIVER=database-uuids

RESEND_WEBHOOK_SECRET=whsec_value_from_the_resend_webhook_page
RESEND_WEBHOOK_TOLERANCE=300

DATABASE_BACKUP_RETENTION_DAYS=14
DATABASE_BACKUP_MAX_AGE_HOURS=26
DATABASE_BACKUP_TIMEOUT_SECONDS=300
MYSQLDUMP_BINARY=mysqldump
FAILED_JOB_ALERT_THRESHOLD=1
```

Leave `DATABASE_BACKUP_PATH` unset to store compressed backup files under the account-private `storage/app/private/backups` directory. That directory must not be inside `public/`. The backup command writes MySQL credentials to a temporary mode-0600 option file, streams `mysqldump` directly into gzip, removes partial backups on failure, and prunes backups older than the configured retention period:

```bash
php artisan app:backup-database
php artisan app:production-status
php artisan queue:failed
```

Hostinger hPanel cron schedules use UTC. Add custom cron jobs using the absolute paths shown by your hosting account, replacing the example account and project paths:

```cron
0 18 * * * /usr/bin/php /home/u123456789/domains/example.com/vibe-app/artisan app:backup-database
15 * * * * /usr/bin/php /home/u123456789/domains/example.com/vibe-app/artisan app:production-status
* * * * * /usr/bin/php /home/u123456789/domains/example.com/vibe-app/artisan queue:work database --stop-when-empty --tries=4 --timeout=30
```

`18:00 UTC` is `02:00 Asia/Manila` on the following calendar day. Test each command over SSH before saving it in hPanel, then review its execution output in hPanel. Keep at least one encrypted off-host copy of the database backup; a backup stored only in the same hosting account does not protect against account or server loss. Test restoration into a separate database periodically, never over the live database:

```bash
gunzip -c storage/app/private/backups/database_YYYYMMDD_HHMMSS.sql.gz | mysql --defaults-extra-file=/home/u123456789/restore.cnf separate_restore_database
```

The temporary `restore.cnf` should be readable only by the hosting account (`chmod 600`) and removed immediately after the restore test. If Hostinger does not expose `mysqldump`, `mysql`, or PHP process execution on the plan, use hPanel's database backup/export and import facilities instead and retain the same off-host-copy and restore-test policy.

For a repeatable SSH deployment, review `deploy-hostinger.sh`, make it executable once with `chmod 750 deploy-hostinger.sh`, and run it from the project root. It intentionally does not pull code or alter `.env`. It installs verification dependencies, clears stale caches, runs the full test suite, creates a pre-migration backup, enters maintenance mode, installs production-only dependencies, runs forced migrations, runs Laravel production optimization, reloads long-running services, and brings the application back up. Its exit trap attempts to leave maintenance mode if a later step fails.

After the migration has been deployed, configure a Resend webhook with endpoint `https://your-domain.example/webhooks/resend` and subscribe to `email.sent`, `email.delivered`, `email.delivery_delayed`, `email.bounced`, `email.complained`, `email.failed`, `email.suppressed`, `email.opened`, and `email.clicked`. Copy its `whsec_...` signing secret into `RESEND_WEBHOOK_SECRET`, then run `php artisan config:clear` or complete the deployment workflow. The endpoint verifies the raw request body and Svix signature, rejects requests when the secret is absent, deduplicates retries by `svix-id`, and correlates events with the originating order email.

Operational records are stored in `order_email_deliveries`, `resend_webhook_events`, and `order_audits`. Failed asynchronous jobs remain in Laravel's `failed_jobs` table and the email job also writes a critical log after exhausting retries. Review `storage/logs/laravel-*.log`, `php artisan queue:failed`, and `php artisan app:production-status` when a status check fails. After the cause is fixed and the job has been retried successfully, remove its reviewed failure record with `php artisan queue:forget UUID`. Do not remove audit records as part of routine queue cleanup.

## Tailwind CDN constraint

This starter intentionally follows the no-Node.js, CDN-only requirement. Tailwind's official browser CDN is convenient because it removes the build step, but Tailwind documents it as a development option rather than its preferred production setup. For a high-traffic production site, replace the browser CDN with a precompiled static Tailwind stylesheet when a separate build process becomes available; the Laravel backend and shared-hosting layout do not need to change.

Official references: [Laravel deployment](https://laravel.com/framework/docs/deployment), [DreamHost web directories](https://help.dreamhost.com/hc/en-us/articles/360041534491-Changing-the-web-directory-assigned-to-a-domain), and [Tailwind Play CDN](https://tailwindcss.com/docs/installation/play-cdn).
